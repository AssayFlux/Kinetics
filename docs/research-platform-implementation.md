# Research Platform integrated implementation delivery

**Owner direction (2026-11-08):** implement Research Platform R1–R10 as one integrated delivery; prepare the first local Android build before the later testing campaign. Do not stop at R1 to request permission to begin R2.

## Implemented source layer

- R1: Android arm64/Python/Rust/C++ feasibility probes and local build script remain in place. The Gradle Android NDK version is pinned to match the local build script; Chaquopy explicitly includes the repository `python/` source package, and the manual runtime probe imports `kinetics` and exercises representative package APIs. Local APK build and Android runtime results are outstanding.
- R2: Compose research shell, SQLite job/provenance tables, SAF document picker and WorkManager streaming-import/hash worker. The store now has a v1-to-v2 migration and completed imports are encrypted with Android Keystore AES-256-GCM in app-private no-backup storage; decrypted analysis materialization is restricted to the app-private cache and a callback helper deletes its temporary plaintext file in a finally block; the manual on-device runtime probe also checks AES-GCM round-trip and AAD rejection; provenance and encrypted storage location are committed transactionally. Partial/resumable staging is now stored as independently authenticated AES-GCM chunks with job/index AAD; resume verifies the source prefix by decrypting chunks in memory, torn final records are truncated before retry, and materialization verifies the recorded whole-file SHA-256 before publishing plaintext. A private-cache callback helper now materializes verified plaintext for a local consumer and deletes it in a finally block; it is not yet wired to a scientific analysis dispatcher or SAF export. SAF export now streams authenticated input to a user-selected document after a complete verification pass; SQLite v2-to-v3 migration is present, and queued/running imports are re-enqueued after process restart only when persisted read permission remains. Encrypted paths are canonicalized into the dedicated no-backup directory. Key-loss recovery, interrupted-export cleanup, orphan reconciliation, migration fixtures and device verification remain incomplete. The store now removes stale uniquely-prefixed plaintext analysis cache files older than 24 hours at startup. The data-pack installer revalidates manifest path fields, hashes the exact copied byte stream, enforces size/checksum before finalization and refuses overwriting an installed version.
- R3: initial sequence, protein and enzyme-kinetics primitives. The kinetic fit now rejects non-finite inputs and reports residual mean/dispersion, R-squared and assumption-qualified Gaussian least-squares AIC/BIC; a separate seeded paired-bootstrap percentile-interval helper is now available, with explicit IID/grid/identifiability caveats; independent reference validation and stronger identifiability analysis remain open. Regression tests cover input validation and diagnostics, but these are software tests, not independent scientific validation. Reference datasets, unit-aware analysis, external concordance and device benchmarks remain open.
- R4: FASTA/FASTQ (including wrapped FASTQ), sequence statistics, reverse complement, transcription, k-mers, global pairwise alignment, strict SAM/VCF text parsing (including CIGAR query-length consistency and valid missing-QUAL semantics), a bounded streaming BAM core-field decoder, FASTQ quality summaries and terminal low-quality trimming. Added a streaming FASTA iterator and reference-checked minimal/left normalization for biallelic literal A/C/G/T small variants. BAM core-field decoding is now available for bounded gzip/BGZF-compatible streams; auxiliary tags are skipped. CRAM, adapter trimming, multiallelic decomposition, symbolic/breakend normalization and variant interpretation remain open.
- R5: PDB and mmCIF `_atom_site` coordinate parsing, geometric contacts and coordinate RMSD with an optional Horn-quaternion rigid-body superposition implementation. mmCIF parsing is deliberately limited to atom-site coordinate loops; symmetry, assemblies and full dictionary semantics are not interpreted. Secondary structure, SASA, hydrogen bonds, salt bridges and disulfide analyses remain open.
- R6: multi-record SDF V2000 plus conservative V3000 atom/bond graph parsing with coordinate/bond validation, graph descriptors, bounded exact element/bond-order substructure matching, and resource-capped exploratory path fingerprints/Tanimoto similarity. Stereochemistry, aromaticity sanitization, protonation/tautomer handling and production RDKit-equivalent behavior remain open.
- R7: Newick parsing/serialization with quoted labels, leaf listing, patristic distances, UPGMA, neighbour joining and Jukes–Cantor corrected nucleotide distances feeding neighbour joining. ML/Bayesian inference, rate heterogeneity, bootstrap and tree search remain open.
- R8: CPM/CLR normalization, finite-input-checked Pearson correlation, log2 fold change, cross-omics correlation, logistic growth and Shannon/Gini-Simpson diversity. Added exploratory two-group Welch tests with Student-t p-values and Benjamini–Hochberg q-values for pre-normalized/log-scale inputs; an exploratory NB2 count GLM with numeric covariates and caller-encoded batch indicators is now available; dispersion moderation, small-sample calibration, repeated measures, robust outlier handling and independent reference validation remain open.
- R9: streaming NCBI Gene gene_info importer now preserves the complete 16-column annotation record, including taxonomy, GeneID, symbols, synonyms, cross-references, chromosome, map location, gene type, nomenclature, designations, source and release metadata; a bounded search helper covers official symbols, synonyms, descriptions, identifiers and nomenclature fields. Versioned PGx star-allele definition ingestion and conservative matching for explicitly complete phased haplotypes are now foundations; no authoritative PGx data pack, comprehensive gene coverage, diplotype/phenotype translation or clinical implementation is claimed. The catalogue is expandable and not represented as exhaustive.
- R10: capability registry validation now checks that implementation paths exist inside the repository. A static Android guard checks offline permissions, backup/cleartext settings, pinned SDK/NDK/ABI, 16 KB linker flags and absence of Android build/device tasks in GitHub Actions. Automated CI is manual-dispatch only under the build-first/test-later instruction; R10 now has a written threat model, accessibility audit protocol and release checklist; reproducible local Gradle/Chaquopy pins and static guardrails are strengthened. Full SBOM/transitive license resolution, security review, accessibility audit, benchmark evidence, signing and device verification remain incomplete.

The capability registry distinguishes source-implemented from validated. Current entries are implemented with no validation evidence; none is marked validated or device-verified.

## Known unfinished scope

This is an integrated implementation increment, not a claim that every R1–R10 exit criterion is satisfied. Outstanding work includes BAM/CRAM and robust VCF normalization; full mmCIF dictionary/assembly/symmetry semantics; secondary-structure/SASA/H-bond/salt-bridge/disulfide analysis; production-grade chemistry and stereochemistry; model-based phylogenetic inference/search and bootstrap support; count-aware differential-expression models and richer omics/multi-omics workflows; catalogue data-pack management, comprehensive gene-domain annotations and PGx allele/diplotype definitions; and full R10 accessibility/performance/crash/security/release automation. The current mmCIF atom-site parser, Horn-quaternion superposition, neighbour joining and Welch/BH routines still require independent reference validation. R1 SciPy and production scientific-engine decisions also remain open.

Simple alignment, graph fingerprints, protein pI estimates and kinetic grid fitting are exploratory implementations. They must not be presented as independently validated scientific results. Clinical mode remains disabled; no patient workflow or patient data is included.

## Build-first / test-later policy

- First APK build is local, not in GitHub Actions.
- No Android emulator/device testing is scheduled in GitHub Actions.
- Source checks are manual-dispatch only; no push/PR workflow is configured during the build-first/test-later phase. They are not a substitute for the later device-validation campaign.
- Do not publish an AAB or claim release readiness until R10 and the owner release gate are complete.
