# Research Platform integrated implementation delivery

**Owner direction (2026-11-08):** implement Research Platform R1–R10 as one integrated delivery; prepare the first local Android build before the later testing campaign. Do not stop at R1 to request permission to begin R2.

## Implemented source layer

- R1: Android arm64/Python/Rust/C++ feasibility probes and local build script remain in place. The Gradle Android NDK version is pinned to match the local build script; Chaquopy explicitly includes the repository `python/` source package, and the manual runtime probe imports `kinetics` and exercises representative package APIs. A reproducible arm64 debug APK/AAB was built in CI run #1904 (commit 30d19ea); artifact integrity, APK ZIP alignment, native ELF alignment and Android JVM unit tests passed. Physical-device runtime, cold-start/memory probes and engine go/no-go remain outstanding.
- R2: Compose research shell, SQLite job/provenance tables, SAF document picker and WorkManager streaming-import/hash worker. The store now has a v1-to-v2 migration and completed imports are encrypted with Android Keystore AES-256-GCM in app-private no-backup storage; decrypted analysis materialization is restricted to the app-private cache and a callback helper deletes its temporary plaintext file in a finally block; the manual on-device runtime probe also checks AES-GCM round-trip and AAD rejection, but this probe has not yet been executed on a physical device; provenance and encrypted storage location are committed transactionally. Partial/resumable staging is now stored as independently authenticated AES-GCM chunks with job/index AAD; resume verifies the source prefix by decrypting chunks in memory, torn final records are truncated before retry, and materialization verifies the recorded whole-file SHA-256 before publishing plaintext. A private-cache callback helper now materializes verified plaintext for a local consumer and deletes it in a finally block; it is not yet wired to a scientific analysis dispatcher or SAF export. SAF export now streams authenticated input to a user-selected document after a complete verification pass; SQLite v2-to-v3 migration is present, and queued/running imports are re-enqueued after process restart only when persisted read permission remains. Encrypted paths are canonicalized into the dedicated no-backup directory. A startup Keystore-alias check now distinguishes definite key absence from an unavailable Keystore; definite loss moves completed encrypted records and retained encrypted partial imports to `recovery_required`, preserves ciphertext, and never generates a replacement key. This is a preservation/status mechanism, not cryptographic recovery: without the original key the data remains unreadable. Interrupted-export provider cleanup, migration fixtures and device verification remain incomplete. A report-only encrypted orphan inventory now reconciles finalized .kdat and partial .encpart files against database references without deleting or decrypting ciphertext; JVM tests cover missing-job, stale-partial, active-partial and symlink cases. The store now removes stale uniquely-prefixed plaintext analysis cache files older than 24 hours at startup. The data-pack installer revalidates manifest path fields, hashes the exact copied byte stream, enforces size/checksum before finalization and refuses overwriting an installed version.
- R3: initial sequence, protein and enzyme-kinetics primitives. The kinetic fit now rejects non-finite inputs and reports residual mean/dispersion, R-squared and assumption-qualified Gaussian least-squares AIC/BIC; a separate seeded paired-bootstrap percentile-interval helper is now available, with explicit IID/grid/identifiability caveats; local Jacobian-based leverage/Cook's distance/Durbin–Watson and identifiability diagnostics are now included, with a host-side SciPy curve_fit comparison harness now executed in pinned CI on deterministic synthetic fixtures; this is numerical implementation agreement, not experimental scientific validation. Independent experimental reference validation remains open. Regression tests cover input validation and diagnostics, but these are software tests, not independent scientific validation. Reference datasets, unit-aware analysis, external concordance and device benchmarks remain open.
- R4: FASTA/FASTQ (including wrapped FASTQ), sequence statistics, reverse complement, transcription, k-mers, global pairwise alignment, strict SAM/VCF text parsing (including CIGAR query-length consistency and valid missing-QUAL semantics), a bounded streaming BAM core-field decoder, FASTQ quality summaries and terminal low-quality trimming. Bounded FASTA QC and explicit-Phred FASTQ quality-summary cards are now connected to Android Explore through Chaquopy; exact-source ARM64 build and regression tests passed CI #2033. These cards are not yet the complete SAF import → durable job → provenance → result/export pipeline. Added a streaming FASTA iterator and reference-checked minimal/left normalization for biallelic literal A/C/G/T small variants. BAM core-field decoding is available for bounded gzip/BGZF-compatible streams; an optional host-side pysam/HTSlib adapter supports BAM/CRAM with explicit local reference for CRAM. Neither pysam/HTSlib nor CRAM is integrated into Android. Adapter trimming, multiallelic decomposition, symbolic/breakend normalization and variant interpretation remain open.
- R5: PDB and mmCIF `_atom_site` coordinate parsing, geometric contacts, coordinate RMSD with optional Horn-quaternion superposition, approximate deterministic Shrake–Rupley SASA, and distance-only N...O hydrogen-bond, canonical Lys/Arg–Asp/Glu salt-bridge and Cys SG disulfide candidate screening. mmCIF parsing remains limited to atom-site loops; symmetry, assemblies and full dictionary semantics, secondary-structure assignment, hydrogen geometry/protonation-aware interaction analysis and reference validation remain open.
- R6: multi-record SDF V2000 plus conservative V3000 atom/bond graph parsing with coordinate/bond validation, graph descriptors, bounded exact element/bond-order substructure matching, and resource-capped exploratory path fingerprints/Tanimoto similarity. Stereochemistry, aromaticity sanitization, protonation/tautomer handling and an optional RDKit host adapter now provides sanitization, canonical SMILES, standard descriptors and Morgan fingerprints when RDKit is installed. It is not packaged in Android; its exact release, transitive licenses, ABI and binary footprint still require review.
- R7: Newick parsing/serialization with quoted labels, leaf listing, patristic distances, UPGMA, neighbour joining, Jukes–Cantor corrected nucleotide distances and seeded nonparametric alignment-site bootstrap split support for JC+NJ. Failed bootstrap replicates are counted and excluded from the support denominator with explicit warnings. Maximum-likelihood/Bayesian inference, rate heterogeneity, model selection and tree search remain open.
- R8: CPM/CLR normalization, finite-input-checked Pearson correlation, log2 fold change, cross-omics correlation, logistic growth and Shannon/Gini-Simpson diversity. Added exploratory two-group Welch tests with Student-t p-values and Benjamini–Hochberg q-values for pre-normalized/log-scale inputs; an exploratory NB2 count GLM with numeric covariates and caller-encoded batch indicators is now available; dispersion moderation, small-sample calibration, repeated measures, robust outlier handling and independent reference validation remain open.
- R9: streaming NCBI Gene gene_info importer now preserves the complete 16-column annotation record, including taxonomy, GeneID, symbols, synonyms, cross-references, chromosome, map location, gene type, nomenclature, designations, source and release metadata; a bounded search helper covers official symbols, synonyms, descriptions, identifiers and nomenclature fields; a new bounded catalogue coverage report summarizes supplied snapshot counts and missing annotations without inventing an expected-gene denominator. Versioned PGx star-allele definition ingestion and conservative matching for explicitly complete phased haplotypes are now foundations; no authoritative PGx data pack, comprehensive gene coverage, diplotype/phenotype translation or clinical implementation is claimed. The catalogue is expandable and not represented as exhaustive.
- R10: capability registry validation now checks that implementation paths exist inside the repository. A static Android guard checks offline permissions, backup/cleartext settings, pinned SDK/NDK/ABI and 16 KB linker flags. CI builds exact-source unsigned arm64 debug APK/AAB artifacts and runs automated checks; no emulator or physical-device test is run. R10 has a written threat model, accessibility audit protocol and release checklist; reproducible local Gradle/Chaquopy pins and static guardrails are strengthened. Full SBOM/transitive license resolution, security review, accessibility audit, benchmark evidence, signing and device verification remain incomplete.

The capability registry distinguishes source-implemented from validated. Current entries are implemented with no validation evidence; none is marked validated or device-verified.

## Known unfinished scope

This is an integrated implementation increment, not a claim that every R1–R10 exit criterion is satisfied. Outstanding work includes BAM/CRAM and robust VCF normalization; full mmCIF dictionary/assembly/symmetry semantics and secondary-structure assignment; production-grade chemistry and stereochemistry; maximum-likelihood/Bayesian phylogenetic inference, rate heterogeneity, model selection and tree search; count-aware differential-expression models and richer omics/multi-omics workflows; catalogue data-pack management, comprehensive gene-domain annotations and PGx allele/diplotype definitions; and full R10 accessibility/performance/crash/security/release automation. The current mmCIF atom-site parser, Horn-quaternion superposition, neighbour joining and Welch/BH routines still require independent reference validation. R1 SciPy and production scientific-engine decisions also remain open.

Simple alignment, graph fingerprints, protein pI estimates and kinetic grid fitting are exploratory implementations. They must not be presented as independently validated scientific results. Clinical mode remains disabled; no patient workflow or patient data is included.

## Integrated build-and-test cycle (D-016)

- D-016 supersedes every earlier build-first/test-later interpretation: substantial increments are built and tested before acceptance as the next baseline.
- GitHub Actions builds unsigned arm64 debug APK/AAB artifacts and runs automated source checks, pinned reference fixtures, static package checks and Android JVM tests.
- No Android emulator/device testing is currently provided by this workflow. Exact-artifact emulator and physical-device installation/runtime checks remain separate required evidence, not a blanket deferred campaign.
- CI validates the exact committed source snapshot. A green run establishes build and listed automated checks only; it does not prove real-device runtime, independent scientific validity, complete licensing or release readiness.
- Do not publish a release AAB or claim release readiness until R10 and the owner release gate are complete.
